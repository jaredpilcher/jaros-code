### [REQ-1] Three-Layer Maximal-Help Prompt

The probe must compose a single prompt that stacks THREE deepening layers for each
target function:

1. **RETRIEVED CONTEXT** — `enriched_file_context` from `repo_context.py` (direct-dependency
   helper signatures + small bodies), not the whole file.
2. **WORKED EXAMPLE** — one solved example taken from a DIFFERENT corpus task: its
   (parent version -> committed fixed version) before/after + the example task's commit intent.
   HONEST: the example is always a different sha from the target; the target task's hidden
   oracle answer is NEVER included.
3. **DECOMPOSITION** — an explicit numbered step-by-step implementation plan generated by
   `_g_plan` from `harness/decomp_probe.py`.

The three layers are combined with the visible failing test (the spec) and the current
function into one maximal-help prompt, then sent to the model (temp=0) to produce a
corrected implementation. Output is piped through the proven indentation-repair layer.

A pure `_build_maxhelp_prompt` helper must be exported so offline tests can inspect
prompt content without calling the LLM.

#### Acceptance Criteria
- [ ] `_build_maxhelp_prompt()` constructs the prompt with all three layers visible in the text
- [ ] Layer 1 (retrieved context) from `enriched_file_context` is present in the prompt
- [ ] Layer 2 (worked example) from a DIFFERENT task sha is present in the prompt
- [ ] Layer 3 (decomposition plan) from `_g_plan` is present in the prompt
- [ ] The target task's own oracle/solution is NEVER included in the prompt
- [ ] `_g_code_maxhelp()` calls `_build_maxhelp_prompt`, sends to LLM at temp=0, applies indentation-repair
- [ ] `_build_worked_example()` picks the first corpus task whose sha differs from the target AND has one cleanly changed function
- [ ] `_core_maxhelp_probe()` inner loop is pure (no git I/O), fully testable offline with injectable stubs

### [REQ-2] Honest Oracle Scoring

The probe must score all implementations via the hidden oracle (`_run_nodes` red->green).
The oracle must be called ONLY after generation — score-only, never shown to the model.
`probe_task_maxhelp` must mirror the git setup/teardown pattern from `passk_probe` and
`decomp_probe` (checkout parent + commit tests, then run the inner loop, then `_reset`).

The `_worked_example` parameter must accept "auto" (build from corpus), None (no example),
or a pre-built dict (offline tests), so tests can inject without any git calls.

#### Acceptance Criteria
- [ ] Oracle called after generation only — score-only, never influences the prompt
- [ ] `probe_task_maxhelp` checkouts parent + commit tests before building layers
- [ ] `_worked_example="auto"` builds from corpus; dict override works for offline tests
- [ ] Repo files are restored to parent state after probe (pass or fail)
- [ ] Skips tasks with no target functions or >4 targets (same caps as other probes)

### [REQ-3] Entry Point and Verdict Reporting

`run_maximal_help(n=6)` must load the first N hard [fail] tasks from `bigbar_jaros.txt`
via `_parse_fail_shas` / `_resolve_tasks` (same as EXT-019/EXT-020), probe each with
the maximal-help strategy, report per-task (cracked? yes/no) and an overall summary
table with Wilson CI, and print an explicit VERDICT comparing against the known raw 0/8
baseline. A `--n N` CLI argument (default 6) must be present.

#### Acceptance Criteria
- [ ] Task loading uses `_parse_fail_shas` + `_resolve_tasks` (same as EXT-019/EXT-020)
- [ ] Per-task cracked/not-cracked progress printed during run
- [ ] Summary table with Wilson95 CI
- [ ] Explicit VERDICT: if >0 cracked -> "HARNESS-DEEPENING HELPS"; if 0 -> "DOES NOT HELP, route to decorrelated model"
- [ ] `--n N` CLI argument (default 6); entry via `python -m harness.maximal_help_probe --n 6`
